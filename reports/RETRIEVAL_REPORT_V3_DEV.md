## 1. Protocol

- Data: patients in `train` + `val` (69 patients, 77 eyes); `test` patients excluded by assertion. Question text: **dev** paraphrases only (5 per type), rotated across instances; the locked file is not read by this runner.
- Same answer key for every strategy: `ground_truth_v2.answer_key` (not imported by the new retriever).
- New system: `intent.parse_intent` → `intent_retrieval.retrieve` (`intent_v3`). An abstention on an answerable question scores 0 on every retrieval metric.
- Baselines: frozen v1 strategies (`combined` α frozen from the v1 snapshot, `rule_router`, `random`) and fixed rules. **The best fixed rule per type is selected here on dev** and frozen in `results/v3_dev/selected_baselines.json` for any later locked evaluation.
- Uncertainty: 95% patient-cluster bootstrap (1000 reps), eye-macro averaging. It does **not** include paraphrase variability: only 5 dev paraphrases per type.
- **Circularity caveat:** for Tier-B types the new operations implement the frozen definitions, so a correct parse gives ≈1.0 by construction (rule coverage). The informative quantities are parser/routing accuracy on *independent* text and abstention behaviour, and dev text is not independent of the parser that was built on it.

## 7. Limitations

- All numbers are development numbers on text the parser was built against. They do not estimate performance on new phrasings.
- 5 paraphrases per type: parser accuracy is a count, not a rate with a defensible CI.
- `max_leakage` is answered with `unavailable_variable` (the variable is not in memory by design), so its Hit@1 is 0. This is the intended behaviour unless a proxy policy is approved (decision D1).
- The developer had prior exposure to the locked paraphrases (see `docs/RETRIEVAL_IMPROVEMENT_PLAN.md`); lexicon terms recognised as locked-only were removed, but contamination cannot be excluded.
- Prime-only types rest on 25–32 dev patients; TREX eyes have no week data, so time questions there return `insufficient_data` by design.
